## 3. `_find_peaks` (Lines 11–33)

### 3.1 Overview & Mathematics
An accumulator array in the Hough transform accumulates votes where sinusoidal curves or circles intersect. In real, discrete digital images, noise and discretization cause votes to spread across a cluster of neighboring bins rather than hitting a single isolated bin. Without suppression, a single physical line or circle would be reported dozens of times as slightly shifted duplicate parameters.

`_find_peaks` implements **Local Non-Maximum Suppression (NMS)** over a 2D accumulator grid:
* A cell $(r, c)$ qualifies as a peak **if and only if**:
  1. Its vote count is greater than or equal to `threshold` (`accumulator[r, c] >= threshold`).
  2. Its vote count is equal to the absolute maximum within an $(N \times N)$ local neighborhood (`local_region.max()`).

This collapses wide vote lobes into their single sharpest local center.

### 3.2 Predicted Output & Return Format
* **Return Type**: `list[tuple[int, int]]`
* **Format**: A list of `(row, column)` index tuples indicating the coordinates of local maxima in the accumulator.
* **Example**:
  ```python
  # If the accumulator has a peak of 85 votes at row 250, col 90:
  [(250, 90)]
  ```
* **Edge Case Behavior**:
  * If no cell reaches `threshold`, returns `[]` (empty list).
  * If the accumulator is all zeros, returns `[]`.
  * If multiple flat cells in a plateau share the maximum, all cells matching the max can be returned; in practice, discrete voting creates sharp unimodal peaks.

## 4. `hough_lines` (Lines 38–72)

### 4.1 Overview & Mathematics
Detects infinite straight lines using the Hessian normal form:
$$\rho = x \cos\theta + y \sin\theta$$
where:
* $\rho \in [-D, +D]$ is the perpendicular signed distance from the origin $(0, 0)$ to the line.
* $D = \sqrt{\text{height}^2 + \text{width}^2}$ is the image diagonal.
* $\theta \in [0, \pi)$ is the angle of the normal vector relative to the horizontal x-axis.

**Algorithm Steps:**
1. Determine the diagonal $D$. The $\rho$ axis is discretized into $2D + 1$ bins (offset by $+D$ so $\rho = -D$ maps to index $0$, and $\rho = 0$ maps to index $D$).
2. Discretize $\theta$ into 180 bins spanning $[0, \pi)$.
3. For every edge pixel $(y, x)$, calculate $\rho$ across all 180 $\theta$ angles simultaneously via vectorization:
   $$\vec{\rho} = x \cos(\vec{\theta}) + y \sin(\vec{\theta})$$
4. Increment the accumulator bins `accumulator[rho_idx, theta_idx] += 1`.
5. Extract local peaks exceeding `threshold` using `_find_peaks`.
6. Convert bin indices back to physical $(\rho, \theta)$ values.

### 4.2 Predicted Output & Return Format
* **Return Type**: `list[tuple[float, float]]`
* **Format**: List of `(rho, theta)` tuples where:
  * `rho`: float/int, signed perpendicular distance in pixels from origin $(0, 0)$.
  * `theta`: float, angle in radians $\in [0, \pi)$.
* **Example Output**:
  ```python
  # A horizontal line located at y = 50:
  [(50.0, 1.5707963267948966)]  # rho=50, theta = pi/2 (90 deg)
  
  # A vertical line located at x = 100:
  [(100.0, 0.0)]                 # rho=100, theta = 0 rad (0 deg)
  ```
* **Edge Cases**:
  * Empty edge image: returns `[]`.
  * Too high threshold: returns `[]` (under-detection).
  * Very low threshold: returns multiple candidate lines along strong edges (over-detection).

## 5. `hough_circles` (Lines 78–123)

### 5.1 Overview & Mathematics
A circle in Cartesian space is defined by three parameters: center $(a, b)$ and radius $r$:
$$(x - a)^2 + (y - b)^2 = r^2$$
A full 3D accumulator $(a, b, r)$ would require $H \times W \times (r_{\max} - r_{\min})$ cells, consuming excessive RAM (e.g., $500 \times 500 \times 100 \times 4 \text{ bytes} \approx 100\text{ MB}$) and causing slow iteration.

**2D Slice per Radius Optimization:**
Instead of a single giant 3D volume, `hough_circles` iterates sequentially over candidate radii $r \in [r_{\min}, r_{\max}]$:
1. For a fixed radius $r$, allocate a 2D accumulator of shape $(H, W)$ representing candidate centers $(a, b)$.
2. For every edge pixel $(x_i, y_i)$, the candidate centers lying on a circle of radius $r$ satisfy:
   $$a = x_i - r \cos\theta, \quad b = y_i - r \sin\theta, \quad \theta \in [0, 2\pi)$$
3. Cast votes in the 2D slice for all valid $(a, b)$ falling within image bounds.
4. Run `_find_peaks` on the 2D slice.
5. Record surviving peaks as `(center_x, center_y, radius)`.

### 5.2 Predicted Output & Return Format
* **Return Type**: `list[tuple[int, int, int]]`
* **Format**: List of `(x_center, y_center, radius)` tuples where:
  * `x_center`: horizontal column index of the circle center.
  * `y_center`: vertical row index of the circle center.
  * `radius`: integer radius of the circle in pixels.
* **Example Output**:
  ```python
  # A circle centered at (100, 100) with radius 40:
  [(100, 100, 40)]
  ```
* **Edge Cases**:
  * No edge pixels: returns `[]`.
  * `r_min > r_max`: loop does not execute; returns `[]`.
  * Concentric circles: correctly identified as distinct tuples with identical $(x, y)$ but different $r$.

## 6. `_deduplicate_ellipses` (Lines 129–147)

### 6.1 Overview & Mathematics
Because the Xie & Ji ellipse algorithm iterates over all pairs of edge points $(p_1, p_2)$, multiple pairs lying on the same physical ellipse perimeter will yield nearly identical candidate centers $(x_0, y_0)$ with slight variations in semi-axes.

`_deduplicate_ellipses` performs spatial clustering:
Two detected ellipses $E_1 = (x_1, y_1, a_1, b_1, \alpha_1)$ and $E_2 = (x_2, y_2, a_2, b_2, \alpha_2)$ are treated as duplicates if the Euclidean distance between their centers is less than `merge_distance`:
$$\text{dist}(E_1, E_2) = \sqrt{(x_1 - x_2)^2 + (y_1 - y_2)^2} < \text{merge\_distance}$$

### 6.2 Predicted Output & Return Format
* **Return Type**: `list[tuple[float, float, float, float, float]]`
* **Format**: Filtered list of non-overlapping ellipse tuples `(center_x, center_y, a, b, angle)`.
* **Example**:
  ```python
  # Input with 2 close candidates:
  [(150.2, 100.1, 40.0, 20.0, 30.0), (151.0, 99.8, 39.5, 20.5, 31.0)]
  # Output after deduplication (merge_distance=20):
  [(150.2, 100.1, 40.0, 20.0, 30.0)]
  ```

## 7. `_candidate_minor_axis` (Lines 151–180)

### 7.1 Overview & Mathematics (Xie & Ji 2002)
An arbitrary ellipse is defined by 5 parameters: center $(x_0, y_0)$, semi-major axis $a$, semi-minor axis $b$, and orientation angle $\alpha$. A standard 5D accumulator is computationally prohibitive ($O(N^5)$).

Xie & Ji (2002) proved that if two edge points $p_1 = (x_1, y_1)$ and $p_2 = (x_2, y_2)$ are assumed to be the endpoints of the **major axis**, then 4 parameters are fixed directly:
* Center: $(x_0, y_0) = \left(\frac{x_1 + x_2}{2}, \frac{y_1 + y_2}{2}\right)$
* Semi-major axis: $a = \frac{1}{2}\sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}$
* Orientation: $\alpha = \text{atan2}(y_2 - y_1, x_2 - x_1)$

Now, only **one single parameter remains**: the semi-minor axis $b$.
For any third edge point $p_3 = (x_3, y_3)$, the distance $d$ from center $(x_0, y_0)$ to $p_3$ is:
$$d = \sqrt{(x_3 - x_0)^2 + (y_3 - y_0)^2}$$

The angle $\tau$ between the vector $\vec{d} = (x_3 - x_0, y_3 - y_0)$ and the major axis direction $(\cos\alpha, \sin\alpha)$ has cosine:
$$\cos\tau = \frac{(x_3 - x_0)\cos\alpha + (y_3 - y_0)\sin\alpha}{d}$$

From the standard ellipse equation, the semi-minor axis $b$ satisfies:
$$b^2 = \frac{a^2 d^2 \sin^2\tau}{a^2 - d^2 \cos^2\tau}$$

`_candidate_minor_axis` evaluates this equation. If $p_3$ lies on the candidate ellipse, $b$ yields a real, positive integer $\le a$. Otherwise, it returns `-1`.

### 7.2 Predicted Output & Return Format
* **Return Type**: `int`
* **Format**: An integer representing candidate semi-minor axis $b \in [1, \lfloor a \rfloor]$, or `-1` if $p_3$ is geometrically impossible for this ellipse.
* **Example**:
  ```python
  # Given center (100, 100), a=50, alpha=0, and p3=(100, 130):
  # dx=0, dy=30, d=30, tau=90 deg -> cos_tau=0, sin_tau=1
  # b^2 = (2500 * 900 * 1) / (2500 - 0) = 900 -> b = 30
  30
  ```

## 8. `hough_ellipses` (Lines 183–255)

### 8.1 Overview & Mathematics
Implements the full Xie & Ji (2002) ellipse detection workflow:
1. Extract edge coordinates.
2. Subsample edge points to a maximum of 300 points (reduces point-pair comparisons from millions to manageable bounds while preserving geometry).
3. Loop through all distinct point pairs $(p_1, p_2)$ that satisfy distance bounds $[D_{\min}, D_{\max}]$.
4. Compute candidate center $(x_0, y_0)$, semi-major axis $a$, and angle $\alpha$.
5. Allocate a **1D accumulator** `b_accumulator` of size $a + 1$.
6. For every third point $p_3$, evaluate `_candidate_minor_axis`. If valid, vote in `b_accumulator[b] += 1`.
7. If $\max(\text{b\_accumulator}) \ge \text{threshold}$, record the ellipse $(x_0, y_0, a, b_{\text{best}}, \alpha_{\text{deg}})$.
8. Apply `_deduplicate_ellipses` to merge overlapping detections.

### 8.2 Predicted Output & Return Format
* **Return Type**: `list[tuple[float, float, float, float, float]]`
* **Format**: List of `(x_center, y_center, semi_major, semi_minor, angle_degrees)` tuples:
  * `x_center`: horizontal center coordinate (float).
  * `y_center`: vertical center coordinate (float).
  * `semi_major`: half-length of major axis $a$ in pixels (float).
  * `semi_minor`: half-length of minor axis $b$ in pixels (float).
  * `angle_degrees`: rotation of major axis relative to horizontal in degrees $\in [-180^\circ, 180^\circ]$.
* **Example Output**:
  ```python
  [(160.0, 120.0, 50.0, 30.0, 45.0)]
  ```
* **Edge Cases**:
  * Fewer than 6 edge points: returns `[]` (at least 5 points required to define a conic).
  * Synthetic circular data: detects ellipses where $a \approx b$.

## 9. `draw_shapes` (Lines 260–298)

### 9.1 Overview & Geometry
`draw_shapes` is the designated visualization function in the system. It overlays all detected shapes onto a copy of the original RGB image:
* **Lines**: Drawn in **Red** `(255, 0, 0)` spanning across the entire canvas.
* **Circles**: Drawn in **Green** `(0, 255, 0)`.
* **Ellipses**: Drawn in **Blue** `(0, 0, 255)`.

**Infinite Line Extrapolation Math:**
A detected line is represented by $(\rho, \theta)$. The closest point on the line to the origin is:
$$x_0 = \rho \cos\theta, \quad y_0 = \rho \sin\theta$$
The direction unit vector parallel to the line is $(-\sin\theta, \cos\theta)$.
To guarantee that the line extends across the entire image regardless of angle, two points are projected far along the direction vector by a distance $L = \text{height} + \text{width}$:
$$\text{Point}_1 = (x_0 + L(-\sin\theta), \; y_0 + L\cos\theta)$$
$$\text{Point}_2 = (x_0 - L(-\sin\theta), \; y_0 - L\cos\theta)$$
These two points are connected using `cv2.line`.

### 9.2 Predicted Output & Visual Style
* **Return Type**: `np.ndarray` of shape $(H, W, 3)$ and dtype `uint8`.
* **RGB Color Mapping**:
  * Red `(255, 0, 0)`: Lines
  * Green `(0, 255, 0)`: Circles
  * Blue `(0, 0, 255)`: Ellipses
* **Anti-aliasing**: Uses `cv2.LINE_AA` for smooth rendering without jagged pixel artifacts.
* **Dynamic Thickness**: Adapts automatically to image resolution:
  $$\text{thickness} = \max\left(1, \; \text{round}\left(\frac{\max(H, W)}{400}\right)\right)$$
  (1 px for small images, 2–3 px for high-resolution images).
